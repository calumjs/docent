Docent turns a GitHub repository into a public-facing static website. It reads
the repo — commits, issues, releases, the README — and writes a small site that
explains what the project is, what's been shipping, and what's open. The site
lives in `/docs` inside the same repo, deploys to GitHub Pages, and keeps
itself current through a daily Claude Code Routine.

## Who it's for

A solo maintainer or a small team with a project worth explaining to
non-contributors. Most repos answer "what is this" with a README aimed at
developers who already know roughly what the thing does. When someone arrives
from search, a link, or a conference talk and wants a human-readable answer —
what does it do, is it maintained, what's broken — they get a wall of markdown.

Docent writes that missing layer: an overview that explains the pitch, a status
page that shows open issues grouped by kind, a journal that narrates recent
activity, and a changelog built from release tags.

Docent is not a replacement for API documentation tools like Docusaurus or
MkDocs. Those describe how a library works. Docent describes what a project
*is* — for visitors who may never read the code.

## How it works

Two install commands bring the skill into any Claude Code session. From there,
one conversation sets up the site: Docent reads the repo for design signals,
scaffolds an Astro site under `/docs`, generates the initial content, and opens
a pull request against the default branch.

After merging, a daily Routine keeps the site current. Each run checks whether
the status page, overview, or changelog is stale against its source (open
issues, README, release tags), and decides whether there's enough recent
activity to write a journal post. Nothing goes live without a pull request.

Docent has five modes, each triggered by a natural-language prompt:

- **`init`** scaffolds the `/docs` site and writes the first content.
- **`update`** refreshes the status page and overview as issues and the README
  change.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without touching them.

The generated content — overview, journal posts, status summaries, changelog
entries — lives in `/docs/content/` as structured MDX and JSON. An Astro
template in `/docs/src/` renders it. The two halves are owned separately:
Docent writes the content; you own the presentation.

## Getting started

Install the skill, then open Claude Code and say:

```
set up Docent for this repo
```

Docent walks through the rest. See the
[README](https://github.com/calumjs/docent) for install steps and the
[SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the
full design.
