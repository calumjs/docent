Docent turns a GitHub repository into a public-facing static website. Two install commands bring the skill into any Claude Code session; one conversation sets up the site from there — Docent reads the repo, generates the initial content, and opens a pull request. After merging, a daily Routine keeps the site current with no further intervention.

## Who it's for

A solo maintainer or a small team with a project that deserves a better introduction than a README. The use case is a visitor who arrives from a search result or a shared link and wants a human-readable answer to "what is this and should I care" — and currently gets a wall of Markdown.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the current status, the story so far — for visitors who may never read the code.

## How it works

The skill has five modes:

- **`init`** scaffolds the `/docs` Astro site and writes the first content.
- **`update`** refreshes the status page and overview as issues and the README change.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues without ever touching them.

Generated content lives in `/docs/content/` as structured MDX and JSON. An Astro template in `/docs/src/` renders it. The two halves are owned separately: Docent writes the content; you own the presentation. The site deploys to GitHub Pages — no hosted service, no API keys, no backend. Inference runs through your Claude Code subscription via a Routine.

## Getting started

Install the skill, then open Claude Code and say:

```
set up Docent for this repo
```

Docent walks through the rest. See the [README](https://github.com/calumjs/docent) for the full install steps, or [SPEC.md](https://github.com/calumjs/docent/blob/master/SPEC.md) for the design.
