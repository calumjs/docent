Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and writes content that answers the first question a new visitor has: what is this, and should I care?

## Who it's for

A solo maintainer or small team with a project that deserves a better introduction than a README. The audience is someone arriving from search or a link who wants a human-readable answer before they look at any code.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent covers what a project *is*: the pitch, the status, the recent history — for visitors who might use the project without ever reading the source.

## How it works

Two install commands bring the skill into any Claude Code session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then one conversation sets up the site. Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After merging, a daily Routine keeps the site current. The Routine decides each morning whether to refresh the overview, write a journal post, update the status page, or some combination — based on what has changed in the repo since the last run. Nothing goes live without a pull request.

Docent has five modes, each a self-contained procedure:

- **`init`** scaffolds the `/docs` site and generates the first content.
- **`update`** refreshes the overview, status, and changelog as the repo changes.
- **`digest`** writes a journal post summarizing a period of recent activity.
- **`release`** turns a new git tag into a changelog entry.
- **`triage`** drafts suggested responses to new issues, without touching them automatically.

The generated content lives in `/docs/content/` as MDX and JSON. An Astro template renders it. The two halves are owned separately: Docent writes the content; the template is yours to modify.
