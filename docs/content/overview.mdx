Docent turns a GitHub repository into a public-facing static website. It reads the repo's commits, issues, releases, and README, and writes content for a small site that answers the visitor's first question: what is this project and should I care about it.

## Who it's for

A solo maintainer or small team with a project that deserves a readable public face. README files serve contributors — people who already want to be there. Docent serves everyone else: visitors arriving from search, a link, or word of mouth who want a plain explanation before they commit to reading code.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works, function by function. Docent describes what a project is and why it exists: the pitch, the current state, the story so far.

## How it works

Docent is a Claude Code plugin. Two install commands add it to any Claude Code session. One conversation runs the setup: Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After merging, a daily Routine keeps the site current. The Routine checks what has changed — new issues, a drifted README, new release tags — and decides what to do: refresh the status page, write a journal post, both, or nothing. All output goes through pull requests; nothing lands directly on the default branch.

The generated content lives in `/docs/content/` as structured MDX and JSON. The Astro template in `/docs/src/` renders it. Docent owns the content files; you own the presentation.

## Getting started

In any Claude Code session inside your target repo:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then say: **set up Docent for this repo**

The skill walks through the rest. See the [README](https://github.com/calumjs/docent) for the full install steps, or the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the design.
