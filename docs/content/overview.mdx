Docent turns a GitHub repository into a public-facing static site. It reads the repo — commits, issues, releases, the README — and produces pages that explain what the project is, what's been shipping, and what's currently open. The site lives in `/docs` inside the same repo and deploys to GitHub Pages. No hosted service, no API keys, no backend.

## Who it's for

A solo developer or small team with a project that deserves a better introduction than a README. Docent is useful when someone arrives from a link or a search result and needs a human-readable answer to "what is this, and should I care?" — not a wall of markdown.

If you already have detailed API documentation, that's a different job. Tools like Docusaurus and MkDocs describe how a library works. Docent describes what a project *is*: the pitch, the status, the story so far — for visitors who may never read the code.

## How it works

Docent is a Claude Code plugin. Two install commands add it to any session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Saying "set up Docent for this repo" runs the `init` procedure. It asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates initial content, and opens a pull request.

After merging that PR, a daily Routine keeps things current. Each run checks whether the status page, overview, or changelog has drifted from the repo's current state, decides whether there's enough recent activity to write a journal post, and produces a PR with whatever needs updating — or exits silently if everything's fresh. Nothing goes live without a pull request.

Docent has five modes:

- **`init`** — scaffolds the site and writes the first content
- **`update`** — refreshes content as issues, the README, and tags change
- **`digest`** — writes a journal post summarizing recent activity
- **`release`** — turns a new tag into a changelog entry
- **`triage`** — drafts suggestions for new issues

The generated content lives in `/docs/content/` as MDX and JSON. An Astro template in `/docs/src/` renders it. Docent writes the content; you own the presentation. The two halves are owned separately and can be changed independently.

## Getting started

Install the plugin into any Claude Code session, then say:

> **set up Docent for this repo**

Docent walks through the rest. After merging the generated pull request, enable GitHub Pages under **Settings → Pages → Source → GitHub Actions**, then set up the daily Routine. See the [README](https://github.com/calumjs/docent) for the full steps.
