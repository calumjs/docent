Docent turns a GitHub repository into a public-facing static website. It reads commits, issues, and releases, and writes content that tells the project's story to visitors who may never look at the code. The site lives in `/docs` inside the same repo and deploys to GitHub Pages — no hosted service, no API keys, no backend.

## Who it's for

A solo maintainer or small team with a project that deserves more than a README as its public face. When someone finds the project through a search result, a link, or a recommendation, they want a quick answer to "what is this, and should I care?" — not a wall of contributor-focused markdown.

Docent is not a substitute for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the current status, the story so far — for visitors who might never open a terminal.

## How it works

Two install commands bring the plugin into any Claude Code session. From there, a single conversation sets up the site. Docent asks about tone and cadence, reads the repo for design signals (logo, badges, primary language), picks a visual style, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request. After merging, a daily Routine keeps the site current.

The Routine decides for itself what to do on each run: refresh the status page if issues have changed, write a journal post if enough activity has accumulated, add a changelog entry when a new tag is pushed, or do nothing if everything is already fresh. Every change goes through a pull request — the Routine never pushes directly to the default branch.

The site has five sections:

- **Overview** — what the project is and who it's for (this page)
- **Journal** — posts summarizing recent activity, written on a configurable cadence
- **Status** — open issues grouped and summarized, showing known bugs and in-progress work
- **Changelog** — release notes derived from tags and merged pull requests
- **Report a bug / Request a feature** — forms that open pre-filled GitHub issues

All content lives in `/docs/content/` as MDX and JSON. An Astro template in `/docs/src/` renders it. Docent writes the content; you own the presentation.

## Getting started

Install the plugin in any Claude Code session inside your target repo:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then say: **set up Docent for this repo**

Docent walks through the rest. See the [README](https://github.com/calumjs/docent) for install steps and the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the full design.
