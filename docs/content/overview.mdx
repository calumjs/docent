Docent turns a GitHub repository into a public-facing static website, maintained by the same Claude Code subscription that runs your development work. It reads the repo — commits, issues, releases, the README — and writes a small site that explains what the project is, what's been shipping, and what's open.

## Who it's for

A solo developer or a small team with a project worth explaining to people who won't read the source. Docent is useful when a visitor arrives from search or a link and finds only a README — well-structured for contributors, but not written for someone asking "what is this, and should I care?"

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the current status, the story so far — for visitors who might never read the code.

## What the site includes

After running `init`, the generated site at `username.github.io/project` contains:

- **Overview** — an explanation of what the project does and who it's for, derived from the README
- **Journal** — posts summarizing recent activity, written on a configurable cadence
- **Status** — open issues grouped and summarized, updated on each scheduled run
- **Changelog** — release notes derived from tagged releases and merged PRs
- **Bug report / Feature request** — forms that open pre-filled GitHub issues in a new tab

The content lives in `/docs/content/` as MDX and JSON files. A bundled Astro template renders them. Docent writes the content; you own the presentation.

## How it works

Docent is distributed as a Claude Code plugin. Two install commands bring it into any session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

After that, one conversation sets up the site: Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After merging, one Claude Code Routine keeps the site current. Each day it checks what's changed — issues opened or closed, README edits, new releases — and decides whether to refresh the status page, write a journal post, both, or nothing. Every change goes through a pull request.

Docent has five modes, each a self-contained procedure you can invoke by name:

- **`init`** — scaffolds the `/docs` site and writes the first content.
- **`update`** — refreshes status, overview, and changelog as the repo changes.
- **`digest`** — writes a journal post summarizing recent activity on demand.
- **`release`** — turns a new tag into a changelog entry.
- **`triage`** — drafts suggestions for new issues without touching them.

## Getting started

In any Claude Code session inside the target repo, run the two install commands above, then say:

> set up Docent for this repo

Docent walks through the rest. See the [README](https://github.com/calumjs/docent) for the full install steps, or [SPEC.md](https://github.com/calumjs/docent/blob/master/SPEC.md) for the design.
