Docent turns a GitHub repository into a public-facing static website. It reads
the repo — commits, issues, releases, the README — and writes a small site that
explains what the project is, what's been shipping, and what's open. The site
lives in `/docs` inside the same repo, deploys to GitHub Pages, and updates
itself on a schedule through Claude Code Routines.

## Who it's for

A solo maintainer or small team with a project that deserves a better
introduction than a README. When people arrive from a search result or a shared
link and want a quick answer to "what is this and should I care," they often get
a wall of markdown. Docent replaces that with pages that address the visitor
directly: an overview written for someone who didn't write the code, a running
status of what's open and in flight, and a journal that makes the project's
history readable without parsing the commit log.

Docent is not a replacement for API documentation tools like Docusaurus or
MkDocs. Those describe how a library works. Docent describes what a project
*is* — the pitch, the current state, the story so far — for visitors who might
never read the code.

## How it works

Install the skill into any Claude Code session, then say "set up Docent for this
repo." The skill asks about tone and cadence, reads the repo for design signals,
scaffolds an Astro site under `/docs`, generates initial content, and opens a
pull request.

After merging, a daily Routine keeps the site current. Each morning it checks
what's changed: if the README drifted, the overview gets a fresh pass; if issues
were opened or closed, the status page regenerates; if there's enough activity to
write about, a journal post appears. All changes go through pull requests —
nothing lands on the default branch without a review step.

The site has five sections, each generated by a dedicated skill mode:

- **Overview** — what the project is and who it's for, derived from the README
- **Journal** — narrative posts about recent activity, written when there's something worth reading
- **Status** — open issues grouped and summarized, refreshed on every run
- **Changelog** — release notes built from git tags and merged PRs
- **Report a bug / Request a feature** — forms that open pre-filled GitHub issues

Generated content lives in `/docs/content/` as structured MDX and JSON. An
Astro template in `/docs/src/` renders it. The two halves are owned separately:
Docent writes the content; you own the presentation.

## Getting started

Two commands add Docent to any Claude Code session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then open Claude Code inside the target repo and say "set up Docent for this
repo." See the [README](https://github.com/calumjs/docent) for the full install
walkthrough, including how to enable GitHub Pages and set up the daily Routine.
