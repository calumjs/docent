Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and writes structured content that answers the questions a visitor has before they're willing to read any code.

## Who it's for

Anyone maintaining a project that gets outside visitors: a solo developer with an open-source tool, a small team shipping something internally, a researcher whose work someone might want to use. Docent is useful the moment you find yourself wishing there were a human-readable introduction to your repo — something that explains what the project is and who should care about it, without requiring the reader to understand your folder structure first.

Docent is not a replacement for documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is* — the pitch, the current state, the story so far — for visitors who may never open a code file.

## How it works

Two commands bring the plugin into any Claude Code session. One conversation sets up the site: Docent asks a few questions about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After merging, a daily Routine keeps the content current. Each run checks what's changed — new issues, a revised README, a new tag — and decides whether to refresh the status page, write a journal post, or both. Nothing goes live without a pull request.

Docent has five modes, each a self-contained procedure the skill runs when you ask for it:

- **`init`** sets up the `/docs` site and writes the first content.
- **`update`** refreshes the status page and overview as the repo changes.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without ever touching them automatically.

The generated content — overview, journal posts, status summaries, changelog entries — lives in `/docs/content/` as MDX and JSON. An Astro template in `/docs/src/` renders it. The two halves are owned separately: Docent writes the content; you own the presentation.
