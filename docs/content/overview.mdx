Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and generates a site that explains what the project is, what's been shipping, and what's open. The site lives in `/docs` inside the same repo and deploys to GitHub Pages on merge.

## Who it's for

A solo maintainer or small team with a project worth sharing publicly. The common situation: someone discovers the repo via a link, a search result, or a mention, and lands on a README formatted for contributors — not for curious visitors who haven't decided whether to care yet.

Docent is not a documentation generator like Docusaurus or MkDocs. Those tools describe *how* a library works. Docent describes *what* a project is: the pitch, the current status, the story of what's been shipping. It's for the visitor who might never read the code, not the developer who already cloned it.

## How it works

Two install commands add Docent to any Claude Code session. One conversation sets the site up: Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates initial content, and opens a pull request.

After merging, a daily Routine keeps the site current. Each morning it checks whether the status page is stale (using a hash of the current issue set), whether the overview has drifted from the README, and whether enough has happened to write a journal post. It produces a PR containing whatever combination makes sense — content refresh, new post, both, or nothing. Nothing goes live without a review.

Docent has five modes:

- **`init`** scaffolds the site and writes the first content from the repo's current state.
- **`update`** refreshes the status page and overview as issues and the README change.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without touching them automatically.

The generated content lives in `/docs/content/` as structured MDX and JSON. An Astro template in `/docs/src/` renders it. Content and presentation are owned separately: Docent writes the content; you own the template.
