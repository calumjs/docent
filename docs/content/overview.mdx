Docent turns a GitHub repository into a public-facing static website. It reads the repo — the README, commits, issues, and release tags — and produces a site that explains what the project is, what has been shipping, and what is currently open. The site lives under `/docs` in the same repo, deploys to GitHub Pages, and updates on a schedule.

## Who it's for

A solo maintainer or a small team with a project that deserves more than a wall of markdown. When someone arrives from a search result or a link and wants to know what the project is and whether it's worth their time, the README is usually the wrong document. It's written for contributors, not visitors. Docent generates something different: a short, structured site aimed at the person who doesn't know what they're looking at yet.

A developer building a tool for other developers is the typical case. The project has users, or could have users, but the entry point is too technical to work as a landing page. Docent doesn't replace documentation — it provides the introduction that documentation assumes you don't need.

## How it works

Docent is a Claude Code skill. Install it with two commands, then run its `init` mode and it asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request. After merging, two manual steps enable GitHub Pages and wire up a daily Routine.

The Routine runs on a schedule. Each day it checks whether the overview, status page, or changelog has drifted from the current repo state and regenerates whatever has. On days when enough has shipped, it also writes a journal post. Nothing goes live without a pull request.

Docent has six modes:

- **`init`** scaffolds the site and writes the first content.
- **`update`** refreshes content as issues, the README, and tags change.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without touching them.
- **`suggest`** files feedback about Docent itself.

Generated content — overview, journal posts, status summaries, changelog entries — lives in `/docs/content/` as MDX and JSON. An Astro template in `/docs/src/` renders it. The two halves are owned separately: Docent writes the content; the Astro template is yours to modify.

## Getting started

Install the skill into your repo, then open Claude Code and say:

```
set up Docent for this repo
```

The `init` mode walks through the rest. See the [README](https://github.com/calumjs/docent) for the full install steps.
