Docent turns a GitHub repository into a public-facing static website, generated from the repo's own commits, issues, and releases. The site lives in `/docs`, deploys to GitHub Pages, and stays current through a scheduled Claude Code Routine — no hosted service, no API keys, no backend.

## Who it's for

A maintainer with a project that deserves a better introduction than a README. Visitors who arrive from a search result or a link often want to know what the thing is, whether it's active, and what's broken — before they read any code. A wall of markdown answers that badly.

Docent answers it with a small site: an overview in plain language, a status page showing open issues grouped by type, a journal of recent activity, and a changelog drawn from release tags. Forms for reporting bugs and requesting features open pre-filled GitHub issues in a new tab — no backend, no form handling.

## How it works

Docent is a Claude Code plugin. Two install commands bring it into any Claude Code session. From there, one conversation sets up the site: the skill reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After the PR merges, two steps complete the setup: enabling GitHub Pages (via Settings or the `gh` CLI), and scheduling the update Routine. The Routine runs daily, checks what's stale or new, and decides whether to refresh content, write a journal post, both, or nothing — based on what's happened in the repo since the last run. Each decision produces a pull request; nothing goes live without one.

Docent can also be invoked on demand: "Docent, write a journal post about the auth refactor."

## Getting started

Install the plugin from within any Claude Code session in your target repo, then say: **"set up Docent for this repo."** The skill walks through the rest.

See the [README](https://github.com/calumjs/docent) for install steps, or [SPEC.md](https://github.com/calumjs/docent/blob/master/SPEC.md) for the full technical design.
