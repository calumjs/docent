Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and writes a small site that explains what the project is, what has been shipping, and what is open. The site lives in `/docs` inside the same repo, deploys to GitHub Pages, and stays current through a scheduled Claude Code Routine.

## Who it's for

A solo maintainer or small team with a project that deserves a better introduction than a README. When people arrive from a search result or a shared link, they want a readable answer to "what is this and should I care" — not a wall of markdown.

Docent is not an API documentation tool. It doesn't describe how a library works; it describes what a project *is*: the pitch, the current status, the story so far — for visitors who may never read the code.

## What the site includes

Once set up, the generated site provides:

- **Overview** — an AI-written explanation of the project and who it's for
- **Journal** — posts summarizing recent activity, written on a configurable cadence
- **Status** — open issues grouped and summarized, updated on each run
- **Changelog** — human-readable release notes derived from git tags and merged PRs
- **Bug report / feature request** — forms that open pre-filled GitHub issues in a new tab

No hosted backend. No API keys beyond your Claude Code subscription. Forms stay within GitHub.

## How it works

Two install commands bring the skill into any Claude Code session. From there, one conversation runs `init`: Docent reads the repo, asks about tone and cadence, scaffolds an Astro site under `/docs`, generates initial content, and opens a pull request.

After the PR merges, one `/schedule` command sets up a daily Routine. Each morning it checks what has drifted since the last run — issues opened or closed, README changed, new release tags — and produces another PR with whatever needs updating. It also decides, based on recent activity, whether to write a journal post. Nothing goes live without a pull request.
