Docent takes a GitHub repository and builds a public-facing static website from it. It reads the repo's README, commits, open issues, and release tags, then writes a set of pages explaining what the project is, what has shipped recently, and what is currently open. The site lives in `/docs`, deploys to GitHub Pages, and refreshes itself daily through a scheduled Claude Code Routine.

## Who it's for

The target user is a solo maintainer or a small team with a project that deserves a clearer introduction than a README. When someone arrives from a link or a search result, a README written for contributors is not a great fit — it assumes familiarity with the toolchain, jumps to install steps, and often buries the "should I care" question several scrolls down.

Docent is not a documentation generator in the Docusaurus or MkDocs sense. Those tools document how a library works. Docent describes what a project *is*: the pitch, the activity log, the current state of open issues — aimed at a reader who may never look at the code.

## How it works

Two install commands add the skill to any Claude Code session. One conversation sets the site up: Docent asks about tone and cadence, scans the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After the PR merges, a daily Routine keeps everything current. Each morning it compares recorded source anchors to the actual state of the repo — issues, README, tags — and produces a PR containing whatever needs updating: a refreshed status page, a new journal post, both, or nothing. All changes go through pull requests.

Docent runs across six modes:

- **`init`** sets up the site and writes the first content.
- **`update`** refreshes status, overview, and changelog as the repo evolves.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** produces a changelog entry from a new tag.
- **`triage`** drafts suggestions for new issues without modifying them.
- **`suggest`** files feedback about Docent itself.

The generated content — MDX and JSON — lives in `/docs/content/`. An Astro template in `/docs/src/` renders it. Docent owns the content; you own the presentation.

## Getting started

Install the plugin, then open Claude Code inside your target repo and say "set up Docent for this repo." See the [README](https://github.com/calumjs/docent) for install steps and prerequisites, or the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the full design.
