Docent turns a GitHub repo into a public-facing static site, generated and updated by a Claude Code Routine rather than a person. It reads your commits, issues, releases, and README, then writes five pages: an overview, a journal, a status page, a changelog, and bug/feature forms. The site deploys to GitHub Pages via your repo's `/docs` folder.

## What you get

A site at `username.github.io/project` with:

- **Overview** — a prose explanation of what the project is and who it's for, generated from your README
- **Journal** — posts summarizing recent activity, written automatically on a configured cadence or on demand
- **Status** — open issues grouped and summarized from your GitHub issue tracker
- **Changelog** — release notes derived from tags and merged PRs
- **Report a bug / Request a feature** — forms that open pre-filled GitHub issues in a new browser tab

## Who it's for

A solo maintainer or a small team with a project that gets traffic from search or links but currently presents visitors with a wall of markdown. Docent is not an API documentation tool — it won't replace Docusaurus or MkDocs. It's for the pitch and the narrative: what the project is, what's been shipping, what's open.

## How it works

Docent is a Claude Code plugin. Two install commands add it to any session, and one conversation runs the initial setup: Docent asks about tone and cadence, scaffolds an Astro site under `/docs`, generates the first batch of content, and opens a pull request. After the PR merges, a Claude Code Routine keeps the site current — running daily, checking what's stale, and deciding whether to refresh the status page, write a new journal post, or both.

Nothing posts without a PR. The generated content lives in `/docs/content/` as MDX and JSON; the Astro template in `/docs/src/` renders it. Docent owns the content; you own the presentation.

[See the README for install instructions](https://github.com/calumjs/docent).
