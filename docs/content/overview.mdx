Docent is a Claude Code plugin that turns a GitHub repository into a public-facing static website. Install it, say "set up Docent," and it scaffolds a site under `/docs` that deploys to GitHub Pages. A daily Routine keeps the site current after that — no manual maintenance required.

## Who it's for

A solo maintainer or a small team with a project that deserves a better introduction than a README. Docent is useful when someone arrives from search or a shared link and wants a human-readable answer to "what is this, and should I care?" — and currently gets raw markdown.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the status, the story so far — for visitors who may never read the code.

## What the site includes

- **Overview** — an AI-written summary of what the project does and who it's for
- **Journal** — posts summarizing recent work, written on a configurable cadence
- **Status** — open issues grouped and explained; known bugs and in-progress work
- **Changelog** — human-readable release notes from tags and merged PRs
- **Report a bug / Request a feature** — forms that open pre-filled GitHub issues

No hosted service, no API keys, no backend. Inference runs through your Claude Code subscription. Forms submit by opening a tab on GitHub.

## How it works

Two install commands add Docent to any Claude Code session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then tell Claude Code: **"set up Docent for this repo."** The skill runs `init` — asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the first content, and opens a pull request.

After merging, one Routine keeps things fresh:

```
/schedule Docent update daily at 08:00 — prompt: "Docent: run update mode."
```

Each morning the Routine checks what's stale, decides whether to refresh the status page, write a journal post, or both — based on what's happened in the repo since the last run. Nothing goes live without a pull request.

Docent has five modes, each a self-contained procedure:

- **`init`** scaffolds the site and writes the first content
- **`update`** refreshes status and overview as issues and the README change
- **`digest`** writes a journal post summarizing recent activity on demand
- **`release`** turns a new tag into a changelog entry
- **`triage`** drafts suggestions for new issues, without touching them automatically
