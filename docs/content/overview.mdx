Docent turns a GitHub repository into a public-facing static website. It reads commits, issues, releases, and the README, then writes the site content — an overview of what the project is, a journal of recent activity, a status page for open issues, a changelog, and forms for bug reports and feature requests. The site deploys to GitHub Pages from the same repo, with no hosted backend.

## Who it's for

A maintainer who wants visitors to get a human-readable answer to "what is this and should I care" — without rewriting the README or maintaining a separate site.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the status, the story so far — for visitors who may never read the code.

If you have a project that deserves more explanation than a wall of markdown, and you'd rather have a Claude Code session write that explanation than write it yourself, Docent is the tool.

## How it works

Two install commands bring the skill into any Claude Code session. One conversation sets up the site: Docent asks about tone and cadence, scaffolds an Astro site under `/docs`, generates initial content, and opens a pull request. After merging, GitHub Pages serves the site from the repo itself.

A daily Routine keeps the content current. Each run checks whether the status page, overview, or changelog has drifted from the repo's current state, decides whether there is enough recent activity to warrant a journal post, and produces a PR with whatever combination makes sense — a content refresh, a new post, both, or nothing. Nothing goes live without a pull request.

Docent has five modes:

- **`init`** — scaffolds the site and writes the first content.
- **`update`** — refreshes status, overview, and changelog as the repo changes.
- **`digest`** — writes a journal post on demand.
- **`release`** — turns a new tag into a changelog entry.
- **`triage`** — drafts suggestions for incoming issues, without touching them automatically.

The generated content lives in `/docs/content/` as structured MDX and JSON. An Astro template in `/docs/src/` renders it. The two halves are owned separately: Docent writes the content; you own the presentation.

## Getting started

Install the skill, then open Claude Code and say:

```
set up Docent for this repo
```

See the [README](https://github.com/calumjs/docent) for the full install steps, or the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the technical design.
