Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and writes a site that tells the project's story to visitors who may never look at the code.

## Who it's for

A solo maintainer or small team with a project worth explaining beyond the README. When someone arrives from a link or a search and wants to know what the project is and whether they should care, a README gives them a wall of markdown. Docent gives them an overview page, a journal of recent activity, an open-issues summary, and a changelog — generated and maintained automatically.

Docent is not an API documentation tool. Tools like Docusaurus or MkDocs describe how a library works. Docent describes what a project *is*: the pitch, the current state, the story so far — for visitors who might never read the code.

## How it works

Install the skill in any Claude Code session, then say "set up Docent for this repo." The init procedure reads the repo, asks about tone and cadence, scaffolds an Astro site under `/docs`, generates the first content, and opens a pull request.

After the PR merges, a daily Routine keeps the site current. The Routine checks what's changed since the last run — stale overview, new issues, drifted changelog — and decides whether to refresh content, write a journal post, or both. Nothing publishes without a pull request.

Docent has five modes:

- **`init`** — scaffolds the site and writes the first content.
- **`update`** — refreshes the status page and overview as issues and the README change.
- **`digest`** — writes a journal post summarizing recent activity.
- **`release`** — turns a new tag into a changelog entry.
- **`triage`** — drafts suggestions for new issues, without modifying them automatically.

The generated content lives in `/docs/content/` as MDX and JSON. An Astro template in `/docs/src/` renders it. Docent owns the content; you own the presentation.
