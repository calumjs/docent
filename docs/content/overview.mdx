Docent turns a GitHub repository into a public-facing static website. It reads the repo's commits, issues, releases, and README, then generates content for a small site that tells visitors what the project does, what has shipped, and what is open.

## Who it's for

Docent is for solo maintainers and small teams whose projects get linked to from outside but offer no friendlier front door than a README. A developer who follows a link to a project wants to understand what it is in one to two minutes. A README written for contributors does not answer that question well for outsiders.

The site Docent produces is not API documentation. It describes what the project *is* — the pitch, the recent changes, the open issues — for visitors who may never read the code.

## How it works

Two install commands add the skill to any Claude Code session. One conversation runs the `init` procedure: Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content pages, and opens a pull request.

After the PR merges, a daily Routine keeps the site current. The Routine runs `update` mode, which checks whether the status page or overview is stale, decides whether enough has happened to merit a journal post, and opens a pull request if anything changed. Nothing is committed to the main branch without a PR.

The five operational modes:

- **`init`** — scaffolds `/docs` and writes the first content.
- **`update`** — refreshes the status page and overview as issues and the README change.
- **`digest`** — writes a journal post summarizing recent activity.
- **`release`** — turns a new tag into a changelog entry.
- **`triage`** — drafts suggestions for open issues, without touching them.

Generated content — overview, journal posts, status summaries, changelog — lives in `/docs/content/` as structured MDX and JSON. An Astro site template in `/docs/src/` renders it. Docent writes the content; you own the presentation.

## Getting started

Install the skill in any Claude Code session inside the target repo:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then say **"set up Docent for this repo."** The `init` procedure handles the rest. See the [README](https://github.com/calumjs/docent) for the full steps and the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the technical design.
