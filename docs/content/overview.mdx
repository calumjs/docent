Docent turns a GitHub repository into a public-facing static website. It reads
the repo's commits, issues, releases, and README, then writes a site that
explains what the project does, what has been shipping, and what is currently
open. The site lives in `/docs` inside the same repository, deploys to GitHub
Pages, and keeps itself current through a scheduled Claude Code Routine.

## Who it's for

A solo maintainer or a small team whose project deserves more than a README as
its public face. Docent fills the gap between a repository and an explanation
that a visitor who has never touched the code can actually read.

A common scenario: someone arrives from a search result or a link and wants to
know whether this project solves their problem. They are not going to read
source files. Docent gives them something that will — an overview that explains
the pitch, a status page that shows what is working and what is broken, a
journal that tells the story of what has been built.

Docent is not a replacement for API documentation tools like Docusaurus or
MkDocs. Those describe how a library works at the function level. Docent
describes what a project *is*: its purpose, current state, and trajectory —
for visitors who might never look at the code.

## How it works

Two install commands add the skill to any Claude Code session. One conversation
sets up the site: Docent asks about tone and cadence, reads the repository for
design signals, scaffolds an Astro site under `/docs`, generates the initial
content, and opens a pull request.

After the PR merges, a daily Routine keeps the site current. Each run decides
whether to refresh the status page, write a journal post, or both — based on
what has happened in the repository since the last update. Nothing goes live
without a pull request.

Docent runs across six modes:

- **`init`** — scaffolds the site and generates the first content.
- **`update`** — refreshes status, overview, and changelog as the repo changes.
- **`digest`** — writes a journal post summarizing recent activity on demand.
- **`release`** — turns a new tag into a changelog entry.
- **`triage`** — drafts label and priority suggestions for new issues.
- **`suggest`** — files structured feedback about Docent itself.

Generated content — the overview, journal posts, status summary, changelog —
lives in `/docs/content/` as structured MDX and JSON. An Astro template in
`/docs/src/` renders it. The two halves stay separate: Docent owns the content;
you own the presentation.

## Getting started

Install the skill into your repo with two commands, then say:

```
set up Docent for this repo
```

Docent walks through the rest. See the [README](https://github.com/calumjs/docent)
for full install steps, or the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md)
for the design specification.
