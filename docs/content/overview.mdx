Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and writes a small site explaining what the project is, what's been shipping, and what's currently open. The site lives under `/docs`, deploys to GitHub Pages, and stays current through a scheduled Routine. No hosted service, no API keys, no backend.

## Who it's for

A solo maintainer or a small team whose project deserves a better introduction than a README. The gap Docent addresses: someone arrives from a search result or a link, wants to know "what is this and should I care," and gets a wall of markdown.

Docent is not an API documentation tool. It doesn't describe how a library works in detail. It describes what a project *is* — the pitch, the current status, the story so far — for visitors who may never read the code.

## How it works

Two commands add the skill to any Claude Code session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

From there, one conversation sets up the site. Docent asks about tone and update cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After the PR merges, a single Routine keeps the site current. Each run decides for itself what to do — refresh the status page, write a journal post, both, or nothing — based on what's happened in the repo since the last run. Nothing goes live without a pull request.

Docent also runs five modes on demand:

- **`init`** scaffolds the site and generates the first content.
- **`update`** refreshes status, overview, and changelog as things change.
- **`digest`** writes a journal post on request ("write a post about the auth refactor").
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts summaries for new issues, without modifying them.
