Docent turns a GitHub repository into a public-facing static website. It reads your README, commits, issues, and releases, then generates a site that answers the visitor's first question: what is this project and should I care? The site lives in `/docs`, deploys to GitHub Pages, and updates on a schedule through Claude Code Routines.

## Who it's for

A solo maintainer or small team whose project deserves more than a wall of markdown. Docent is most useful when people arrive from search or a shared link and need a plain-language answer — not an API reference, not a getting-started guide, just a readable explanation of what the project is, what's been happening, and what's currently open.

It is not a replacement for documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the recent story, the open threads — for visitors who may never read the code.

## How it works

Two install commands bring the skill into any Claude Code session. From there, one conversation sets up the site: Docent reads the repo for design signals, asks about tone and cadence, scaffolds an Astro site under `/docs`, generates the first content, and opens a pull request.

After merging, a daily Routine keeps the site current. Each morning it checks whether the status page, overview, or changelog has drifted; if recent activity is substantial enough to write a journal post, it folds that in too. The result is always a PR — never a direct push — containing exactly the changes that made sense to make.

Docent has six modes:

- **`init`** scaffolds the site and writes the first content.
- **`update`** refreshes the status page, overview, and changelog as the repo changes.
- **`digest`** writes a journal post summarizing recent activity on demand.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without touching them directly.
- **`suggest`** files feedback about Docent itself.

Generated content — overview, journal posts, status summaries, changelog — lives in `/docs/content/` as structured MDX and JSON. An Astro template in `/docs/src/` renders it. Docent writes the content; you own the presentation.

## Getting started

Install the skill into your repo, then open Claude Code and say:

```
set up Docent for this repo
```

Docent walks through the rest. See the [README](https://github.com/calumjs/docent) for the full install steps, or the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for the design.
