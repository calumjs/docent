Docent turns a GitHub repository into a public-facing static website. It reads the repo's commits, issues, releases, and README, then writes and maintains a site that explains what the project is, what's been happening, and what's currently open. The site lives in `/docs`, deploys to GitHub Pages, and updates itself on a schedule.

## Who it's for

A solo maintainer or small team with a project that deserves a better introduction than a wall of markdown. Visitors who arrive from search or a shared link want a plain answer to "what is this and should I use it" — not a developer-oriented README with installation steps as the lede.

Docent fills that gap. It is not an API documentation tool. Docusaurus and MkDocs describe how a library works; Docent describes what a project *is* — the pitch, the current status, the story so far — for people who might never read the code.

## How it works

Docent is a Claude Code plugin. Two install commands bring the skill into any Claude Code session. One conversation sets up the site: Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After the PR merges, a daily Routine keeps the content current. On each run, the Routine checks whether the status page, overview, or changelog have drifted from their sources. When enough has happened to tell a story — typically three or more merged PRs since the last post — it also writes a journal post. Nothing goes live without a pull request.

Docent has six modes. Each is a discrete procedure:

- **`init`** scaffolds `/docs` and writes the first content.
- **`update`** refreshes what's stale and, on active days, writes a journal post.
- **`digest`** writes a journal post on demand.
- **`release`** generates a changelog entry from a new tag.
- **`triage`** summarizes new issues without modifying them.
- **`suggest`** files feedback about Docent itself as a GitHub issue.

The content — overview, journal posts, status summaries, changelog — lives in `/docs/content/` as MDX and JSON. An Astro site in `/docs/src/` renders it. Content and presentation are separately owned: Docent writes the content; you own the presentation.

## Getting started

Install the plugin, then say "set up Docent for this repo" in a Claude Code session. Docent handles the rest.

See the [README](https://github.com/calumjs/docent) for full install steps and the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md) for design details.
