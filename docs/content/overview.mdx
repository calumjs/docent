Docent is a Claude Code plugin that reads a GitHub repository — its commits, issues, releases, and README — and writes a static website that explains what the project is to visitors who might never read the code.

## What it's for

Most project READMEs answer "how do I install this?" They're less good at answering "should I care about this at all?" Docent fills that gap. It produces a public-facing site at `username.github.io/project` with pages that address a non-contributor directly: what the project does, what's been shipping lately, what's broken and what's coming.

It's useful for a solo maintainer or a small team that has something worth sharing publicly but doesn't have time to maintain a separate documentation site. If people find your project from a link or search result and currently land on a wall of markdown, Docent gives them something more readable.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the status, the story so far — for visitors who might never read the code.

## How it works

The site lives in `/docs` inside your repo and deploys to GitHub Pages. No hosted service, no API keys, no backend. Inference runs through your Claude Code subscription.

After a one-time setup, a daily Routine keeps the site current. The Routine checks whether the README has changed, whether the issue set has shifted, and whether enough has happened recently to be worth a journal post. When something is stale or there's something worth writing about, it opens a pull request. Nothing goes live without one.

The content lives in `/docs/content/` as structured MDX and JSON. An Astro site template in `/docs/src/` renders it. The two halves are owned separately: Docent writes the content; you own the presentation.

Docent has five modes:

- **`init`** — one-time setup: scaffolds the site, generates initial content, opens a PR.
- **`update`** — daily maintenance: refreshes the overview and status page when their sources drift, and decides whether to write a journal post.
- **`digest`** — writes a journal post on demand, summarizing a specific period.
- **`release`** — turns a new tag into a changelog entry.
- **`triage`** — drafts suggestions for new issues, without touching them automatically.

## Getting started

Two install commands bring the skill into any Claude Code session inside your target repo. See the [README](https://github.com/calumjs/docent) for the full steps. After installing, say "set up Docent for this repo" and the `init` procedure walks through the rest: tone, cadence, domain; site scaffolding; initial content; PR.

After merging, a single `/schedule` command sets up the Routine that keeps everything current. You can also invoke Docent manually anytime: "Docent, write a journal post about the recent changes."
