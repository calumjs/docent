Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and writes content that explains what the project is, what's been shipping, and what's open. The site lives in `/docs` inside the same repo, deploys to GitHub Pages, and updates itself on a schedule through Claude Code Routines. No hosted service, no API keys, no backend.

## Who it's for

A solo maintainer or small team whose project has more visitors than contributors. When someone finds your repo through search or a link and wants a plain-English answer to "what is this and should I care," a README wall isn't the right surface. Docent writes the site that answers that question.

Docent is not an API documentation tool. Docusaurus and MkDocs cover how a library works. Docent covers what a project *is*: the pitch, the current status, the story so far — for visitors who might never read the code.

## How it works

Two install commands bring the skill into any Claude Code session. From there, one conversation sets up the site: Docent reads the repo for design signals, asks a few questions about tone and cadence, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After that, a daily Routine keeps the site current. Each run checks whether the README has changed, whether the issue set has shifted, whether anything new has shipped — and produces a PR with whatever combination makes sense. Content regenerates on its own; the only tokens spent are from your Claude Code subscription.

The site has five sections: an overview of what the project is, a journal of recent activity, a status page with open issues grouped by theme, human-readable release notes, and bug/feature request forms that open pre-filled GitHub issues.

## Getting started

See the [README](https://github.com/calumjs/docent) for the full install steps. Two plugin commands, then open Claude Code and say: **"set up Docent for this repo."** Docent walks through the rest.

After the init PR merges, enable GitHub Pages (Settings → Pages → Source → GitHub Actions) and set up the daily Routine — both are covered in the README.
