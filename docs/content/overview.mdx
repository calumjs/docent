Docent is a Claude Code plugin that reads a GitHub repository — its README, commits, open issues, and release tags — and produces a static website explaining what the project is. The site lives in `/docs` inside the same repo, deploys to GitHub Pages automatically, and stays current through a scheduled Routine that runs on your Claude Code subscription.

## Who it's for

A maintainer who has a project worth showing to people who aren't already contributors. The typical problem: someone arrives from a search result or a link, lands on a wall of technical README, and can't quickly tell whether this is something they want.

Docent is not a documentation generator. Tools like Docusaurus and MkDocs explain how a library's API works. Docent answers a different question — "what is this, who is it for, and what's happening with it" — for a visitor who may never read the code.

## What it produces

A live site at `username.github.io/project` with five sections:

- **Overview** — a plain-language explanation of the project, written from the README and repo signals
- **Journal** — posts summarizing recent activity on a cadence you configure
- **Status** — open issues, grouped and summarized
- **Changelog** — release notes derived from tags and merged PRs
- **Bug / feature forms** — pages that open pre-filled GitHub issues in a new tab

No hosted service, no backend, no API keys beyond your existing Claude Code subscription.

## How it works

Two install commands add the plugin to any Claude Code session:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then say "set up Docent for this repo." The `init` procedure asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After merging, you enable GitHub Pages with Actions as the source and schedule a daily Routine. The Routine runs `update` mode each morning: it checks what's stale, decides whether there's enough activity for a journal post, and opens a PR with whatever combination makes sense — content refresh, new post, both, or nothing.

All changes go through a PR. The skill writes content; it never pushes directly to your default branch.
