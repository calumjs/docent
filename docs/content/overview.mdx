Docent turns a GitHub repository into a public-facing static website. It reads the repo — commits, issues, releases, the README — and produces a small site that tells visitors what the project is, what has been shipping, and what is open. The site lives in `/docs` inside the same repo, deploys to GitHub Pages, and stays current through a daily Claude Code Routine.

## Who it's for

A solo maintainer or small team with a project that gets visitors from search or a shared link. Those visitors currently get a README — markdown formatted for contributors, not for people who need to decide whether this project solves their problem.

Docent fills that gap. It writes an overview that answers "what is this and should I care," a status page that surfaces open issues by theme, a changelog derived from release tags, and a journal that summarizes recent activity. None of that requires writing a separate site or maintaining a blog.

Docent is not an API documentation tool. For libraries that need function-by-function reference pages, use Docusaurus or MkDocs. Docent is for the layer above that: what the project is, who it is for, and what has shipped.

## How it works

Docent is a Claude Code plugin distributed via the plugin marketplace. It ships a skill (`skills/docent/`) and an Astro site template (`docs/src/`). The skill reads the repo and writes structured content — MDX files and JSON — into `docs/content/`. The Astro template renders that content into a static site.

Five modes cover different situations: `init` scaffolds the site from scratch; `update` keeps the status page, overview, and changelog current; `digest` writes a journal post on demand; `release` turns a new tag into a changelog entry; `triage` drafts suggestions for new issues without touching them automatically.

After setup, a daily Claude Code Routine runs `update` mode. On each run, it compares source anchors recorded in content files against the current repo state and regenerates only what has drifted. If there is enough journal-worthy activity since the last post, it writes one. Nothing goes to the default branch without a pull request.

## Getting started

Install the plugin in any Claude Code session inside your target repo, then say "set up Docent for this repo":

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

From there, the skill handles the rest: asks about tone and cadence, reads the repo, scaffolds the site, and opens a pull request. After merging, enable GitHub Pages (source: GitHub Actions) and set up the daily Routine. See the [README](https://github.com/calumjs/docent) for the full steps.
