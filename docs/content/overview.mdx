Docent turns a GitHub repository into a public-facing static website. It reads commits, issues, releases, and the README, then writes a site that explains what the project is, what has shipped, and what is open. The site lives under `/docs` in the same repository, deploys to GitHub Pages, and updates on a schedule through a Claude Code Routine.

## Who it's for

A solo maintainer or small team whose project gets external interest but whose only front door is a README. When someone finds a repository via search or a shared link, they often get a wall of Markdown. Docent generates a site that answers "what is this and should I care" — a human-readable overview, a journal of recent activity, an issue-grouped status page, and release notes — without any hosted service, API keys, or backend.

If you already have dedicated API documentation (Docusaurus, MkDocs, Sphinx), Docent is a complement. Those tools describe how a library works. Docent describes what a project *is*: the pitch, the current state, the story so far — for visitors who may never read the code.

## How it works

Docent is a Claude Code plugin. Two commands install it into any Claude Code session. From there, saying "set up Docent for this repo" runs the `init` procedure: it reads the repo for design signals, picks one of four visual vibes, scaffolds an Astro site under `/docs`, generates the initial content, and opens a pull request.

After merging, two steps finish the setup: enabling GitHub Pages with Actions as the source, and scheduling the daily Routine. The Routine runs once a day, checks what's stale, and opens a PR with whatever needs updating — a refreshed status page, a new journal post, both, or nothing. It produces output only when there's something worth producing.

You can also invoke Docent directly in any Claude Code session: "Docent, write a journal post about the auth refactor" calls the `digest` mode on demand.
