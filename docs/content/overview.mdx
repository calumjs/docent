Docent turns a GitHub repository into a public-facing static website. It reads the repo's commits, issues, releases, and README, then generates content that describes the project to visitors who won't read the source — what it is, who it's for, what has shipped, and what is open.

The site lives in `/docs` inside the same repository and deploys to GitHub Pages. There is no hosted service, no backend, and no API keys. Content generation runs through a Claude Code subscription via a daily Routine.

## Who it's for

A solo maintainer or small team with a project that gets visitors from search, a link, or word of mouth — people who want a human-readable answer to "what is this and should I care," and currently land on a README.

Docent is not a replacement for API documentation tools like Docusaurus or MkDocs. Those describe how a library works. Docent describes what a project *is*: the pitch, the current state, the story so far — for people who might never touch the code.

## What it generates

Each run produces some combination of:

- **Overview** — a description of what the project does and who it's for, derived from the README
- **Journal** — posts summarizing recent activity, on a configurable cadence
- **Status** — open issues grouped by theme, refreshed when the issue set changes
- **Changelog** — release notes derived from tags and merged PRs
- **Bug report / Feature request forms** — pages that open pre-filled GitHub issues

## How it works

Two install commands bring the skill into any Claude Code session. From there, one conversation handles the rest: Docent asks about tone and cadence, reads the repo for design signals, scaffolds an Astro site under `/docs`, generates the first content, and opens a pull request.

After merging, a daily Routine keeps the site current. Each run checks what's stale, decides whether there's enough new activity to write about, and produces a PR with whatever combination makes sense — content refresh, new journal post, both, or nothing if the site is already up to date.
