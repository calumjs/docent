Docent turns any GitHub repository into a public-facing, self-maintaining website. It reads your commits, issues, releases, and README, and generates a small site that explains what the project is, what has been shipping, and what is open — without a database, a backend, or any hosted service.

## Who it is for

Docent is for a solo maintainer or a small team with a project that deserves a better introduction than a wall of README. When someone arrives from a search result or a link and asks "what is this and should I care," a README often answers poorly — it is written for contributors who already know the context. Docent produces a site aimed at that outside visitor instead.

It is not a replacement for API documentation tools like Docusaurus or MkDocs, which describe how a library works. Docent describes what a project *is*: the pitch, the current status, the story so far.

## How it works

Docent is a Claude Code plugin — two commands to install, one conversation to set up:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then say **"set up Docent for this repo."** The skill reads the repository, picks a visual style, scaffolds an Astro site under `/docs`, generates an overview, a status page, a changelog, and an inaugural journal post, and opens a pull request.

After that PR merges, a daily scheduled task keeps the site current. Each morning it checks what has changed — open issues, the README, any new release tags — and produces a PR containing whatever needs updating: a fresh status page, a regenerated overview, a journal post summarizing recent work, or any combination of those. Nothing goes live without a pull request.

The site deploys to GitHub Pages at `username.github.io/project`. No separate API key is required; inference runs through your Claude Code subscription.

Docent has five modes, each a procedure the skill runs when you ask for it:

- **`init`** scaffolds the `/docs` site and writes the first content.
- **`update`** refreshes the status page and overview as issues and the README change.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without touching them automatically.

The generated content — overview, journal posts, status summaries, changelog — lives in `/docs/content/` as structured MDX and JSON. An Astro site template in `/docs/src/` renders it. The two halves are owned separately: Docent writes the content; you own the presentation.
