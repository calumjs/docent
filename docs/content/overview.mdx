Docent reads a GitHub repository and writes a static website that explains what the project is, what has been happening, and what is open. No hosted service, no backend, no manual updates — two install commands and a daily Routine handle the rest.

## Who it's for

A solo maintainer or a small team with a project that deserves more than a README. When someone arrives from a link or search result, they currently get a wall of markdown. Docent produces a proper introduction instead: an overview for newcomers, a journal of recent activity, a status page grouping open issues, and a changelog derived from tags and merged PRs.

If your project has a public audience — users, potential contributors, curious passers-by — Docent gives them something worth reading. If your project is entirely internal or library-only, it offers less.

## How it works

Install the skill into a Claude Code session inside your target repo, then say "set up Docent for this repo." The skill reads your README, commits, issues, and releases; analyzes the repo for visual signals (badges, metadata); scaffolds an Astro site under `/docs`; generates initial content; and opens a pull request.

After merging, two manual steps complete the setup: enable GitHub Pages with GitHub Actions as the source, and schedule the daily Routine. The Routine runs each morning, checks what has changed in the repo since the last run, and opens a PR containing whatever combination of updates makes sense — a refreshed status page, a new journal post, both, or nothing. Nothing goes live without a pull request.

Docent has five modes, each a self-contained procedure:

- **`init`** scaffolds `/docs` and writes the first content.
- **`update`** refreshes status and overview as issues and the README change.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** converts a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without touching them automatically.

Content lives in `/docs/content/` as MDX and JSON. An Astro template in `/docs/src/` renders it. Docent writes content; the presentation layer is yours to modify.
