Docent turns a GitHub repository into a public-facing static website. It reads
the repo — commits, issues, releases, the README — and writes a small site that
explains what the project is, what's been shipping, and what's open. The site
lives in `/docs` inside the same repo and deploys to GitHub Pages. No hosted
service, no API keys, no backend: inference runs through your Claude Code
subscription.

## Who it's for

A solo maintainer or a small team with a project that deserves a readable
introduction. Docent is useful when people arrive from a link or search result
and want a human-readable answer to "what is this and should I care?" — and
currently find a README.

Docent is not a replacement for API documentation tools like Docusaurus or
MkDocs. Those describe how a library works. Docent describes what a project
*is*: the pitch, the current status, the story so far — for visitors who may
never read the code.

A practical example: you've built a CLI tool for your team. Developers who use
it know how it works. But someone from another team hears about it and searches
for it. Without Docent, they land on a README with install steps and a wall of
flags. With Docent, they land on an overview explaining why the tool exists, a
status page showing what's being worked on, and a journal showing what shipped
last week.

## How it works

Docent is a Claude Code plugin. Two install commands bring it into any session.
One conversation sets up the site: Docent asks about tone and cadence, reads the
repo for design signals, scaffolds an Astro site under `/docs`, generates the
initial content, and opens a pull request.

After merging, a daily Routine keeps the site current. The Routine decides for
itself whether to refresh content, write a journal post, or both — based on what
has happened in the repo since the last run. Nothing goes live without a pull
request.

Docent has five modes:

- **`init`** scaffolds the site and writes the first content.
- **`update`** refreshes the status page, overview, and changelog as the repo
  changes.
- **`digest`** writes a journal post summarizing recent activity.
- **`release`** turns a new tag into a changelog entry.
- **`triage`** drafts suggestions for new issues, without ever touching them
  automatically.

The generated content lives in `/docs/content/` as structured MDX and JSON. An
Astro template in `/docs/src/` renders it. The two halves are owned separately:
Docent writes the content; you own the presentation.

## Getting started

Install the plugin in any Claude Code session inside your repo:

```
/plugin marketplace add calumjs/docent
/plugin install docent@docent
```

Then say:

> **set up Docent for this repo**

Docent walks through the rest. See the [README](https://github.com/calumjs/docent)
for full install steps, or the [SPEC](https://github.com/calumjs/docent/blob/master/SPEC.md)
for the design.
